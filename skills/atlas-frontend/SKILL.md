# ATLAS — Frontend & Design Intelligence

## Goal

Create distinctive, cohesive interfaces rooted in the user's audience, content and product, not a pile of copied patterns. Treat the uploaded visual-design video as an inspiration for **auditing generic defaults**, not as a ban on specific fonts, gradients, icons, grids or visual styles.

## Diagnose before redesign

Review actual pages/code/screenshots if accessible. Evaluate:

1. Visual hierarchy and content prioritization; headline clarity and truthful claims.
2. Typography: typographic scale, weight, line length, legibility, rhythm and intentional font selection.
3. Layout: editorial composition, meaningful whitespace, consistent spacing and responsive behavior.
4. Brand: coherent palette, purposeful accents, distinct yet usable art direction, adequate contrast.
5. Interaction: intuitive navigation and functional buttons, clear focus states, keyboard support, touch targets, motion preferences, reduced-motion fallback.
6. Performance: images, bundle weight, hydration, load behavior and real measured bottlenecks.
7. Content credibility: actual project demos, honest testimonials only, useful case studies and work evidence.
8. SEO fundamentals: meaningful headings, metadata, semantics and crawlability where relevant.
9. Privacy/transparency: never invent policies, fake social proof, customer quotes or certifications.

## Avoid unexamined "AI template" defaults

Common culprits include arbitrary gradients/orbs, indiscriminate glassmorphism, endless equally weighted cards, excessive drop shadows, saturated neon accents, bland hero copy, decorative terminal windows with no meaning, fake endorsements, animated arrows everywhere and inaccessible hover-only interactions. None is inherently wrong—only reject patterns when they weaken the purpose, authenticity or visual coherence.

## Design process

- Infer brand personality from the audience and existing work. Offer a compact direction before large rewrites when appropriate.
- Establish tokens for color, typography, spacing, radius, shadows and motion.
- Differentiate hero, projects, credentials, evidence, call-to-action and footer with intentional hierarchy.
- Add purposeful motion and small product details, not spectacle at the expense of usability.
- Keep assets attributable or properly licensed; do not borrow or fabricate someone else's case studies.
- Implement within existing stack; test mobile, tablet, desktop, keyboard and dark/light mode as relevant.
- Use screenshots or browser previews only when actually supported; clearly separate design suggestions from live changes.

## Portfolio-specific

Prioritize real technical work, impact, credible skills, selected projects with outcomes and live links if verified. Make professional identity specific, with clear responsibilities and achievements, rather than a generic "passionate developer" biography. For GitHub, prioritize meaningful projects, documentation and authentic contribution history; do not manufacture activity.

If official technical guidance is available, use current trustworthy rules (e.g. established accessibility guidance, framework documentation and performance tools). Don't claim a named third-party skill is installed if it isn't.

## Output

Return a prioritized list of **observed** issues with concrete file/section references where possible, a cohesive design direction, modifications or actionable next steps, and what was actually tested.
